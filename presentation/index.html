01

一則訊息背後，是一件待解決的事

當查證要跨系統、處理要跨班別，接手的人需要知道查到了什麼、現在誰負責，以及何時再向玩家更新。

「我的提款顯示已受理，但銀行還沒收到。」

示意情境。客服要先找到正確交易，弄清楚「已受理」代表的進度。

玩家要知道下一步

目前確認了什麼，何時會收到更新，仍有問題時從哪裡續問。

客服要查對資料

分清這次問的是哪一筆，並把來源、查證時間與回覆留在同一案。

主管要看得見責任

知道哪件快到期、卡在哪裡、誰在跟進，以及交班後由誰接手。

這個需求要怎麼驗證？

找營運商、客服與主管回顧最近實際發生的案件，比較現有客服工具、後台與人工協調的做法。確認這類案件是否反覆發生、成本在哪裡、誰能決定採購。

如果現有流程已能查對證據、接續工作並追蹤承諾，就縮小切入範圍。現階段這是待驗證的需求假說。

如果案件更容易處理，誰會為這個價值買單？

02

先驗證工作台的價值，再拓展通路

建議保有獨立產品，先和營運商驗證客服團隊是否願意採用。若接入與支援可重複交付，再評估合作夥伴轉售或供應部分能力。

建議以基礎訂閱、工作容量和可核對用量計費

工作區訂閱可包含基本席次或容量。訊息、AI 等變動成本按可核對用量設計，導入、維運與合作授權另外議定。採購者、付款者與使用者待試點確認。

直售工作台營運商要改善完整客服流程，可直接觀察使用、付費與續約。要負擔銷售、導入及工作習慣轉換。
合作夥伴通路平台已有營運商客群，可探索共同銷售、轉售或 OEM。先談開票、分潤、版本、支援與事故責任。

試點要算哪些成本與成果？

對照導入前後的單案人工時間、重開率與承諾達成。每個工作區再核算獲客、開通、來源適配、訊息、AI、支援與分潤，並記錄付費及續約意向。

如果未來測試 AI 成果計價，先定義解決、重開、人工接手、重複計費與申訴的口徑。正式價格與合作條件待取證。

同一個產品要支援不同交付方式，核心該管哪些事？

03

入口可以不同，案件責任要一致

客服在 PRX 管案件、交班和對客承諾。會員及交易以業務來源為準，訊息管道另行回報投遞結果。提款進度、送達與結案因此能各自追蹤。

同一筆提款，三種狀態

支付方已受理

由業務來源回報。客服可轉述查證結果，到帳時間仍要等來源確認。

管道回報訊息已送達

依據是訊息管道提供的回執。款項進度仍要向業務來源查證。

待客服跟進

由 PRX 記錄主責與承諾。玩家仍在等款項，可以沿用原案追問。

為什麼完整工作台與嵌入面板分開？

完整頁面要讓客服同時處理待辦、對話、查證和交班，並由 PRX 維護自身版本。小型嵌入面板適合在既有後台顯示單項情境，例如查目前由誰負責。

接入既有客服系統時，雙方先約定案件主檔。業務來源帳號、員工登入和訊息管道身分須分別核對，才能連到正確工作區與案件。

營運商怎麼配置工作區和模組？

工作區按品牌與服務範圍管理成員及資料。客服與主管依職責取得操作權限。產品可依需求搭配客服、Bot、品牌外觀及受眾旅程，模組可分開評估及啟用。

用 NGSS3 驗證這套分工，第一條路徑怎麼走？

04

從 NGSS3 查一筆資料，走完一件案

以第一個預期來源 NGSS3 建立可重用的接入驗收方式。先選一個測試工作區、一名客服和一種唯讀查詢，把身分、資料與責任逐一驗清楚。

有證據，才能給出可核對的進度

來源回傳已受理，PRX 留下來源、時間和版本。客服可以告知已知進度，並約定下一次更新。

來源未知，案件仍有主責

查詢逾時時顯示目前無法確認。客服繼續處理仍有權限的案件，安排補查或交班，並告知玩家何時更新。

來源撤權後停止查詢與使用受限明細

PRX 重新檢查可見範圍，畫面與 AI 草稿都須遵守。仍有案件權限的客服可保留跟進責任，改由具權限者查證。

接入之前，各方要準備什麼？
NGSS3
提供去識別的員工、租戶與品牌範例，說明唯讀介面、狀態語義、錯誤、事件與撤權方式。
PRX
盤點能力差距，確認工作區成員資格、案件授權、可保留的資料與稽核方式，並列出待查項目。
營運商
確認測試問題、資料用途、試點窗口、付款與事故責任。三方同意一條可重跑的驗收路徑。
怎麼確保進到正確的工作區？

建議從 NGSS3 安全啟動獨立頁面，由可信服務端驗證員工及短效啟動資訊。PRX 另外核對成員資格、品牌、用途與動作。登入技術待確認。

驗收停權、錯租戶、過期連結、跨品牌同名與查詢結果晚到。瀏覽器傳來的品牌或會員識別須先查驗。憑證由可信服務端管理。

第一件案做到什麼才算通過？

用一種唯讀查詢走完接案、查證、分派主責、必要的交班、回覆及續問。另驗來源斷線、撤權和晚到結果，確保資料不足時客服知道怎麼繼續。

以可重跑的驗收記錄區分合成、契約與授權環境的證據。NGSS3 接入與試點目前仍待驗證。

這條路徑跑通後，哪些證據才值得擴大投入？

05

先證明能維運，再證明能複製

以下是建議的投入門檻。當可靠性、跨來源適配與經濟性分別有證據，再選擇嵌入、合作通路或能力 API。

  1. 把單一來源做穩重送、亂序、失聯與撤權可追查

    記錄連線支援的能力、權限、版本與健康狀態。能驗證事件來源、去重、對帳，並區分受理、完成及未知，才評估擴展連線。

  2. 驗證第二個來源查清共用流程與每次適配成本

    挑一個識別規則、狀態或事件方式不同的來源，確認同一案件流程能共用多少。若授權、識別或狀態語義差異過大，先修正核心分工，再評估限定嵌入。

  3. 選擇可持續的交付方式有採用、付費與支援成本的證據

    依實際開通、單案人工時間、重開、失約、支援與續約情況，決定先做直售、轉售或能力供應。合作前約定資料責任、版本、事故支援與退出方式。

Bot、外觀與旅程可以怎麼發展？

Telegram Bot 可優先探索自助查詢與真人轉接，讓客服能接續案件。品牌外觀與受眾旅程依各自用途、授權及成本驗證，可獨立選用。知識與 AI 先協助客服查證和擬稿，由人審閱。

32 項客服功能，逐一走查

與 Demo 工具箱的「功能走查」同一份清單（資料同源）。先從 8 種日常工作進入 Demo；這裡是備查：每項標著日常入口，展開看操作流程。需要切換情境或示範身份時，使用 Demo 工具箱，情境重置會先經確認。

開啟合成 Demo（新分頁） 展開各項查看操作流程；全部畫面為合成資料。

核心 A · 工作總覽

  1. #1 我的工作待辦按工作項列出；同客戶多案按案號分組，顯示最緊急一項＋另有 N 項。

    日常入口：誰卡住了

    1. 開「我的工作」。
    2. 瀏覽按緊急度排好的工作項。
    3. 點一項進入案件處理。
    4. 處理完回來，列表自動更新。
  2. #2 儲存視圖與篩選四個預設視圖：需我處理／即將到期／等待外部或同事／全部案件；篩選條件會記住。

    日常入口：誰卡住了

    1. 點視圖標籤，列表即時切換。
    2. 再按範圍（我的、待認領、團隊）與狀態細篩。
    3. 切換其他頁面再回來，確認篩選仍在。
  3. #3 待我回應一欄收攏交班邀請、派單邀請、查證待處理；已逾時標「已逾時 · 檢視原案」。

    日常入口：待接受的交班

    1. 開「待我回應」。
    2. 看標籤區分種類。
    3. 點一列直達原案對應位置處理。
  4. #4 案件追蹤跨案件看板：未結／我負責／需要協助／全部；每卡顯示管道、狀態、追蹤是否逾時。

    日常入口：誰卡住了

    1. 開「案件追蹤」。
    2. 選篩選。
    3. 鳥瞰哪些案卡住。
    4. 點卡進入處理。

核心 B · 回覆

  1. #8 公開回覆／內部紀錄分隔同一個輸入框切換「公開回覆」與「內部紀錄」；公開的才傳給客戶。

    日常入口：待回覆

    1. 確認頂部模式（公開／內部）。
    2. 輸入內容。
    3. Ctrl+Enter 送出（Esc 取消匯入）。
    4. 內部紀錄進時間軸但標示為內部。
  2. #9 按案件隔離的草稿每案公開／內部草稿各自獨立；A 案打一半去看 B 案，回來還在。

    日常入口：待回覆

    1. A 案輸入不送出。
    2. 切 B 案輸入。
    3. 切回 A 案，兩邊草稿各自保留。
    4. 分別送出。
  3. #10 回覆模板搜尋、分類、收藏、最近使用；變數自動帶入；無法確認的欄位會被擋下。

    日常入口：待回覆

    1. 按發話區的「回覆模板」。
    2. 搜尋或瀏覽分類。
    3. 預覽內容與變數。
    4. 插入草稿，審閱後送出。
  4. #11 命令列Ctrl／Cmd+K 喚起：切模式、開請教、跳案件、開知識；無權限指令顯示原因。

    日常入口：待回覆

    1. 按 Ctrl+K（Mac 為 Cmd+K）。
    2. 輸入關鍵字。
    3. 選動作或案件，直接執行或跳轉。

核心 C · 時限與承諾

  1. #5 等待對象章案件在等誰一眼標籤：玩家補件／第三方來源／同事接班；暫停中加註。

    日常入口：外部系統轉交

    1. 不用操作，開案即見。
    2. 掃過列表，確認等待中案件卡在哪。
  2. #6 服務水準協議每案取「下一個到期的時計」：逾期紅、即將到期黃、正常、已暫停、已結案。

    日常入口：外部系統轉交

    1. 掃列表看顏色。
    2. 點徽章或進案看時限詳情（定義、規則、起點、完成證據、暫停紀錄）。
  3. #16 四種服務時計首次回覆、後續回覆、解決、對客承諾四條時計；歷史案件起點不足會標示。

    日常入口：外部系統轉交

    1. 進案開時限詳情。
    2. 看四條各剩多少、誰負責。
    3. 該回的回、該暫停的暫停。
  4. #17 承諾改期更改回覆時間：選新時間、填內部原因，再加入對話區回覆；確認送出後才改期。

    日常入口：外部系統轉交

    1. 按「更改回覆時間」，選新時間。
    2. 填內部原因（僅團隊可見），按「加入回覆」。
    3. 有舊草稿時，選合併、取代或取消。

    2. 真的要看內容就走申請，別想繞過。
    3. 不小心點到正文被擋，就去看欄位沒開那一列。

    2. 能不能看來源，還要再過政策跟 Grant 那一關。
    3. 還在等核准（PENDING）或版次不對就等，別一直重刷。

怎麼進來
  • PRX 帳號：點人頭直接進來，掛 PRX Native，不用 NGSS3。
  • NGSS3 登入：跳過去驗完身分再跳回來；不收密碼，登入成功不代表看得到來源。
  • 兩個都綁：同一個人可以兩邊都綁，信箱一樣也不會自動合併，要重驗一次。
報到跟查資料是兩回事
  • 登入只幫你報到，沒發來源資料的門票。
  • 要看來源：你的角色 × 手上案件 × 綁定過的身分 × 欄位，再跟來源 Grant（ACTIVE＋版次）對一次，全部通過才放行。
  • PRX-only 客服沒 NGSS3 也照這套玩；管理員的 JWT 誰都不借。
檢查的順序：誰先誰後
  • 先驗你是誰（Session → 成員 → 工作區），再看案子跟綁定對不對，接著看角色、欄位、Grant 版次，最後看租戶、連線跟 Gateway 健不健康。
  • 任何一關沒過就擋下來；還在等核准（PENDING）不能看，斷線就顯示連不上，不會誤判成被拒絕。
授權現在是什麼狀態
  • 還在等（PENDING_SOURCE）：來源還沒點頭，不能查。
  • 可以用（ACTIVE）：版次對得上才能看，舊版次、新查詢都要重驗。
  • 暫停（PAUSED）：新的先擋下來，手上的案子留著。
  • 收回（REVOKED）：授權被收走，想看就全部重來，舊資料清掉。
  • 過期（EXPIRED）：時間到了，重新申請。
被擋了怎麼辦
  • 來源還沒點頭：去看授權進度等核准，先別查。
  • 來源連不上：手邊的事先做，晚點再試，別拿舊資料當證據。
  • 你的角色不能看：找主管照流程調範圍。
  • 這個欄位沒開：走加開申請，金額不會出現在畫面跟紀錄裡。
  • 授權被收回：別重試，全部重走一次申請。
  • 還沒確認是誰的案子：走合法綁定，別用名字或通訊帳號亂猜。
兩條路長這樣
  • 報到這條路：NGSS3 驗完 → 對到 PRX 成員。
  • 查資料這條路：PRX 政策跟來源 Grant 都點頭 → 模擬 Gateway 只吐你能看的欄位。
  • 兩條路分開驗；前端不直接碰來源，查詢一定走後端認過的案子。
